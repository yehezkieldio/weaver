# Evaluation Methodology: A First Principles Analysis

## Abstract

In a research context, a RAG system cannot be judged merely by "looking good." It requires rigorous, quantitative validation. This document details the **Evaluation Methodology** integrated into the system. The framework is built upon the **RAGAS (Retrieval Augmented Generation Assessment)** paradigm, which decomposes performance into component metrics. This allows researchers to pinpoint whether a failure is due to poor retrieval (Context) or poor reasoning (Generation).

## 1. The RAG Triad

The evaluation strategy focuses on the three core components of any RAG interaction, often referred to as the "RAG Triad":

1.  **Question (Input):** The user's query.
2.  **Context (Retrieval):** The documents found by the system.
3.  **Answer (Output):** The final text generated by the agent.

Also considered is the **Ground Truth**, the ideal answer provided by human annotators (if available).

## 2. Key Metrics (The RAGAS Framework)

The system computes the following metrics for `evaluationRuns`. These are typically calculated using a separate "Judge LLM" (e.g., GPT-4) that scores the interaction.

### 2.1. Faithfulness (Generation)
*   **Definition:** Measures the factual consistency of the generated answer against the retrieved context.
*   **Question:** "Is every claim in the answer supported by the retrieved documents?"
*   **Goal:** Detection of Hallucinations. If the answer contains information *not* present in the source text, Faithfulness drops.

### 2.2. Answer Relevance (Generation)
*   **Definition:** Measures how pertinent the generated answer is to the given prompt.
*   **Question:** "Does this answer actually address the user's question?"
*   **Mechanism:** Often calculated by generating synthetic questions from the answer and checking similarity to the original question.

### 2.3. Context Precision (Retrieval)
*   **Definition:** Measures the signal-to-noise ratio of the retrieved chunks.
*   **Question:** "Are the relevant documents ranked higher than irrelevant ones?"
*   **Importance:** High precision ensures the LLM isn't distracted by irrelevant information.

### 2.4. Context Recall (Retrieval)
*   **Definition:** Measures if *all* the necessary information was retrieved.
*   **Question:** "Did the search engine find all the facts needed to answer the question?"
*   **Requirement:** Requires Ground Truth to calculate accurately.

## 3. Evaluation Pipeline

The evaluation is not an afterthought but a dedicated pipeline in the application (`src/lib/rag/evaluation.ts`).

1.  **Dataset Creation:** A set of "Golden Questions" is defined (stored in `evaluationQuestions`).
2.  **Batch Execution:** The system runs these questions through the RAG engine, recording the `Question`, `Context`, and `Answer`.
3.  **Scoring:** The "Judge LLM" asynchronously reviews the logs and assigns scores (0.0 - 1.0) for each metric.
4.  **Storage:** Scores are written to `evaluationResults`, linked to the specific configuration (e.g., "Hybrid Search vs. Vector Only") used during the run.

## 4. Ablation Studies

The framework is designed to support **Ablation Studies**—systematically removing or changing components to measure their impact.
*   *Experiment:* Disable "Hybrid Search" and use only "Vector Search."
*   *Measure:* Does `Context Recall` drop?
*   *Conclusion:* Hybrid search contributes X% to recall performance.

## 5. Conclusion

The Evaluation Methodology provides the empirical evidence required for academic research. By quantifying "Faithfulness" and "Relevance," the system moves beyond subjective user feedback, allowing for scientific optimization of the Retrieval and Generation algorithms.
